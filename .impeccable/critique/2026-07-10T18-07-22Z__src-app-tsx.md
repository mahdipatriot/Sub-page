- **Responsive layout** (lines 408, 509, 600): `lg:grid-cols-3` with `col-span-2` on status card; `sm:grid-cols-3` on stats; `lg:grid-cols-2` on content. Mobile single-column.
- **Progress ring accessibility** (line 433): `role="progressbar"` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-label`.
- **Module-scoped constants** (lines 21-57): `formatBytes` and `statusConfig` at module scope — no recreation on render. Unused `glow` property removed.
- **Rules of Hooks compliance** (line 147): `normalizedStatus` useMemo moved above early returns.
- **Restrained motion** (lines 199, 208, 410): `animate-fadeIn` kept only on brand title (first impression) and status card (primary content). All other sections appear instantly.

## Priority Issues

### [P3] `animate-fadeIn` on skeleton header (line 208)
**Why it matters**: The skeleton header still has `animate-fadeIn` while the real header (line 322) does not. Minor inconsistency — the skeleton should match the real layout's motion behavior.
**Fix**: Remove `animate-fadeIn` from line 208.

### [P3] `animate-fadeIn` on error card (line 286)
**Why it matters**: The error card has `animate-fadeIn` — this is actually appropriate for an error state (draws attention to the error). Not a real issue, but noted for completeness.

### [P3] `animate-fadeIn` on chart container (line 612)
**Why it matters**: The chart container still has `animate-fadeIn`. This is borderline — the chart is secondary content that appears after the status card, so a subtle entrance is defensible. Could remove for consistency with the no-fadeIn policy on other secondary sections.

### [P3] `dir` variable used only once (line 144, used at line 542)
**Why it matters**: The `useDir()` hook is called to get `dir`, but it's only used in one place (line 542) for the on_hold duration display. Could be inlined, but the hook call itself is the important part — the variable is secondary.
**Fix**: Low priority. Leave as-is — the hook may be needed for future components.
